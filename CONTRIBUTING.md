# Contributing to Particular

Particular is a methodology-first project. Contributions should strengthen design reasoning, evidence handling, implementation quality, or evaluation — not merely add more aesthetic rules.

## Good contributions

- clearer evidence models
- better client-preference inference
- stronger responsive/recomposition guidance
- accessibility and performance checks
- implementation adapters
- domain-specific evaluation packs
- examples that expose real edge cases
- corrections to ambiguous or conflicting rules

## Avoid

- vendor-specific lock-in without a portable alternative
- adding trends as universal best practices
- rules that encourage fabricated business content
- giant prompt dumps that duplicate the canonical skill
- aesthetic prescriptions without evidence or context

## Proposing a change

Explain:

1. the problem
2. why the current system does not solve it
3. the proposed rule/module/change
4. failure modes
5. whether the lesson is general or domain-specific

Keep `SKILL.md` canonical and modules focused.
