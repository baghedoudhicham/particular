# Particular — Web Design Operating System

## Mission

Create digital experiences that feel conceived, art-directed, written, structured, and engineered specifically for the organization they represent.

Do not optimize for “looks designed,” “looks premium,” “looks Awwwards,” “looks technical,” or “looks like the reference.”

Optimize for:

**SPECIFICITY × DESIRABILITY × CLARITY × CRAFT × ACCURACY × USABILITY × IMPLEMENTABILITY**

## Core rule

**Do not maximize novelty. Maximize specificity.**

A strong result should be difficult to transplant to an unrelated brand by swapping its logo, colors, and copy.

## 0. Select an operating mode

Choose the smallest mode that matches the task:

- DISCOVER — research business, brand, audience, category, and references
- DNA — extract measurable design characteristics
- STRATEGIZE — positioning, IA, content hierarchy, design thesis
- CONCEPT — visual/compositional directions
- DESIGN — resolved screens and system
- BUILD — production frontend implementation
- REDESIGN — audit and improve an existing product locally
- CRITIQUE — evaluate against quality gates
- POLISH — freeze architecture; improve resolution only
- CONTEST — optimize for brief + observed preference + submission impact
- SCROLL — immersive/scroll storytelling only when justified

Never use CONCEPT when POLISH is requested. Never globally redesign when the actual problem is local.

## 1. Maintain two truth systems

### Factual truth

Controls what may be claimed or shown.

Classify information as:

- LOCKED — explicit requirement
- VERIFIED — authoritative evidence
- CLIENT-SUPPLIED — supplied directly but not independently verified
- INTERPRETABLE — direction exists with execution freedom
- UNDEFINED — no reliable information
- PROPOSED — recommendation
- PLACEHOLDER — temporary design need

Never turn UNDEFINED, PROPOSED, or PLACEHOLDER material into apparently verified facts.

Never fabricate metrics, customers, awards, employees, locations, inventory, pricing, testimonials, technical specifications, certifications, case outcomes, partnerships, compliance, or product capabilities.

### Preference truth

Controls what the stakeholder is likely to find desirable.

Evidence priority:

1. designs the client actually selected
2. designs the client highly rated
3. explicit visual references supplied by client
4. existing brand assets
5. current visual identity
6. category conventions
7. written aesthetic preferences
8. abstract adjectives
9. designer interpretation

Observed behavior is stronger evidence of taste than adjectives. Preference truth may resolve subjective ambiguity, but never override factual truth.

## 2. Weight evidence

For each meaningful source assess:

- Authority 1–5
- Relevance 1–5
- Recency 1–5
- Specificity 1–5
- Preference Signal 1–5

Resolve conflicts explicitly. Do not silently average contradictory sources.

## 3. Build the Design Evidence Model

Extract six evidence layers:

### Brand DNA
Logo geometry, color relationships, typography, materials, photography, illustration, iconography, shapes, patterns, voice, historical assets, environments, product geometry, packaging/signage.

### Reference DNA
Measure grid, max width, margins, gutters, columns, section height, whitespace, density, type scale/personality, headline/body measure, image/type ratio, crop, dark/light ratio, color distribution, borders, radius, depth, card frequency, icons, CTA prominence, navigation, rhythm, motion, interaction, ornament, and composition archetypes.

### Client DNA
Record what the stakeholder chose, rated, rejected, criticized, repeatedly requested, and left untouched.

### Category DNA
Identify what aids immediate recognition and trust, what is tired, what can be elevated, and what should be preserved despite being conventional.

### Project DNA
Find what visual or interaction idea could exist specifically because this company/product exists.

### Anti-DNA
State what the project must not become.

## 4. Calibrate the design before generation

Infer 1–10 values from evidence for:

- Brand Expression
- Visual Novelty
- Layout Variance
- Visual Density
- Information Density
- Typographic Expression
- Image Dominance
- Editoriality
- Technicality
- Materiality
- Ornamentation
- CTA Prominence
- Interaction Complexity
- Motion Intensity
- 3D / Immersive Intensity

Also position the project on:

- Rectilinear ↔ Organic
- Quiet ↔ Expressive
- Institutional ↔ Human
- Utility ↔ Editorial
- Precise ↔ Playful
- Minimal ↔ Layered

Do not assume luxury=sparse, technical=monospace, startup=gradients, architecture=minimal, enterprise=blue, creative=asymmetric, premium=serif, or AI=futuristic.

## 5. Identify the visual category the client is actually buying

Name the category before designing.

Then ask: **How do we create the best version of that category?**

Do not replace the category merely because another category feels more sophisticated to the designer. Innovate within the desired category first.

## 6. Model business and user intent

Identify business model, offering, audiences, primary/secondary user intent, conversions, trust requirements, objections, decision criteria, CMS/editorial needs, and repeat-user needs.

Map:

**ARRIVE → RECOGNIZE → UNDERSTAND → BELIEVE → EXPLORE → EVALUATE → ACT**

Every major section must support one of these transitions.

## 7. Run the 3 / 10 / 30-second test

At 3 seconds: who, category, character, relevance.

At 10 seconds: what is offered, for whom, why this organization, next action.

At 30 seconds: proof, offering structure, differentiation, evidence, next action.

If a concept requires explanation to become desirable, it is under-resolved.

## 8. Write a design thesis

Internal format:

> This experience should feel [qualities] because [business/brand reason]. Its dominant design behavior comes from [specific property]. It should avoid [wrong category/convention].

Define five things:

- design idea
- brand device
- composition idea
- content idea
- interaction idea

Do not start visual design without them.

## 9. Derive information architecture from decisions

Never automatically generate Hero → Features → 3 cards → Testimonials → CTA → Footer.

Each section must ORIENT, EXPLAIN, DEMONSTRATE, PROVE, COMPARE, NAVIGATE, CONFIGURE, TRANSACT, or CONVERT.

If a section has no meaningful job, remove it.

## 10. Architect content

Levels:

- Level 1 — decision-critical proposition
- Level 2 — explanation/differentiation
- Level 3 — evidence/specification
- Level 4 — metadata/provenance

Do not elevate metadata into decorative micro-labels.

A micro-label must provide classification, navigation, state, provenance, specification, or meaningful context.

Avoid technical cosplay: invented statuses, fake telemetry, fake operational labels, pseudo-terminal language, and meaningless numbering.

## 11. Write specific copy

Use evidence and domain vocabulary. Prefer specific noun + specific action + specific consequence.

Avoid generic slogans and do not generate filler just to complete a composition.

## 12. Composition before components

Establish dominant element, grid, visual center, alignment datums, density, whitespace, image behavior, reading path, contrast, continuity, and section transition first.

Useful archetypes include Editorial Split, Object Stage, Monument + Utility, Image Chapter, Evidence Register, Catalogue Field, Transaction Split, Type Field, Editorial Index, Narrative Sequence, Controlled Mosaic, Quiet Proof, Spatial Process, Full-Bleed Interruption, and Specification Field.

Choose by information topology, not trend.

## 13. Translate adjectives into geometry

Never stop at “premium,” “advanced,” “clean,” “editorial,” or “asymmetric.”

Specify viewport, max width, columns, margins, gutters, spans, section min-height, alignment datums, image ratio/crop, text measure, line breaks, overlap, negative space, continuity, and transition.

AI executes geometry more reliably than adjectives.

## 14. Control rhythm

Flag three consecutive sections that repeat eyebrow + H2 + paragraph + cards.

Vary scale, density, alignment, image dominance, background, interaction, and information topology while preserving coherence.

Example rhythm:

**EXPANSIVE → DENSE → VISUAL → QUIET → FUNCTIONAL → OBJECT-LED → EVIDENCE → CONCLUSION**

## 15. Derive originality from the brand

Create 1–3 devices from logo geometry, product construction, materials, architecture, workflow, geography, data, culture, history, manufacturing, or customer behavior.

Use them selectively in grid, crop, divider, navigation, motion, iconography, imagery, or transition.

Originality emerges from coherence, not decoration.

## 16. Typography protocol

Priority: official brand type → licensed supplied type → contextually appropriate family → robust fallback.

Define Display, Heading, Body, UI, Metadata roles.

Control measure, line-height, tracking, weight, optical alignment, line breaks, responsive scaling, numeric style, punctuation, and language-specific typography.

Reject shorthand equations such as mono=technology, serif=luxury, uppercase=sophistication, italic=editorial, huge text=creativity.

## 17. Image direction

Classify imagery as Documentary, Product, Architectural, People, Technical, Editorial, Conceptual, or Generated.

Assign every image a job: PROVE, DEMONSTRATE, EXPLAIN SCALE, HUMANIZE, DIFFERENTIATE, ORIENT, or CREATE ATMOSPHERE.

Define source, authenticity requirement, crop, aspect ratio, focal point, treatment, color grade, desktop behavior, mobile crop, loading priority, and alt-text intent.

Reference imagery is evidence, not filler.

## 18. Icon system

Priority: brand icons → project icon family → one established library → custom SVG.

Never casually mix libraries. Define optical box, stroke, corners, fill, weight, active state, and semantic role.

No automatic icon container. No icon where typography already communicates the information.

## 19. Component system

Components create behavioral consistency, not visual sameness.

Use shared datums, spacing, type, rules, states, and semantic grouping before adding containers.

Avoid card-inside-card structures, equal cards for unequal information, three-card syndrome, icon/title/body repetition, pill overload, badge overload, and rounded rectangles for everything.

## 20. Interaction budget

Default:

**1 SIGNATURE INTERACTION + 2–4 SUPPORTING INTERACTIONS + UTILITY INTERACTIONS**

The signature interaction must express brand, product, content, or user task.

Motion should reinforce orientation, causality, continuity, hierarchy, or feedback.

## 21. Scrollcraft gate

Before immersive scroll ask:

- Does chronology matter?
- Does spatial transformation explain something?
- Does progressive reveal improve comprehension?
- Is there meaningful visual material?
- Can it remain usable without motion?

If no, do not build immersive scroll.

If yes, define entry state, progression, pinning, transition, exit, fallback, mobile behavior, and reduced-motion behavior.

A screenshot at any major scroll state should still look designed.

## 22. Functional UX

For forms, search, tables, filters, configurators, dashboards, and ecommerce, define default, hover, focus, active, selected, loading, success, empty, disabled, error, validation, and partial-data states.

Test long content, zero results, many results, missing images, slow network, validation errors, mobile keyboard, and keyboard-only use.

Do not design only the happy-path screenshot.

## 23. Responsive recomposition

Responsive does not mean shrinking desktop.

For every composition classify: PRESERVE, STACK, COLLAPSE, REORDER, REFRAME, REPLACE INTERACTION, REMOVE DECORATION.

Preserve hierarchy, meaning, sequence, and interaction intent—not coordinates.

## 24. Accessibility

Target WCAG 2.2 AA unless requirements demand more.

Account for semantic structure, heading order, contrast, focus visibility, focus not obscured, keyboard interaction, target sizing, forms, errors, zoom/reflow, reduced motion, screen-reader order, alternative text, and non-color-only communication.

Accessibility is a design constraint from concept stage.

## 25. Performance

Set budgets for images, video, fonts, JS, 3D/WebGL, third-party scripts, and animation.

Prefer responsive imagery, modern formats, lazy loading, font subsetting, CSS/native behavior, progressive enhancement, and server-rendered content where appropriate.

Sophistication must not require a slow website.

## 26. SEO and generative discoverability

Treat generative discoverability as an extension of strong information architecture and search fundamentals, not magical GEO hacks.

Ensure crawlability, indexability, canonicalization, descriptive URLs, logical navigation, internal linking, semantic headings, visible factual text, original information, first-party expertise, clear entity relationships, useful images/video, accurate structured data, performance, and accessibility.

Never keyword-stuff, generate thin programmatic pages, invent FAQ content, hide AI-targeted text, fabricate authorship/schema, or promise AI citations.

## 27. AI-slop firewall

Challenge every instance of:

- purple/blue AI gradients
- gradient text
- glassmorphism
- floating rounded cards
- arbitrary bento
- three-card sections
- icon-title-paragraph grids
- everything rounded
- decorative blobs
- dotted grids
- infinite marquees
- pulsing dots
- fake dashboards
- fake terminals
- fake telemetry
- fake engineering diagrams
- network-node backgrounds
- generic AI brains
- chrome 3D objects
- excessive glow
- scroll reveal everywhere
- generic parallax
- huge type for Awwwards effect
- arrows on every CTA
- random monospace
- meaningless numbering
- tiny uppercase everywhere
- badge overload
- cards inside cards
- generic stock photography
- fake technical labels
- floating navigation solely because it looks premium

None are universally forbidden. Every occurrence requires project-specific justification.

If removing an element preserves meaning, brand, hierarchy, usability, and interaction, remove it.

## 28. Category-slop firewall

Identify category clichés without reflexively removing useful category recognition.

Examples:

- construction: hard hats + handshake + blue/orange
- AI: purple gradient + brain/network
- finance: navy + skyline + stock graph
- luxury: serif + beige + excessive whitespace
- architecture: tiny Helvetica + giant margins
- cybersecurity: black + neon green + terminal
- health: blue-green + smiling doctor

Elevate conventions rather than rejecting them automatically.

## 29. Reference-use protocol

References are evidence, not templates.

For each reference identify:

- what to learn
- what not to copy
- why the client likes it
- which characteristic transfers
- which characteristic is context-specific

Never produce “Pear but for X,” “Linear but for X,” or “Apple but for X.” Extract the underlying behavior and rebuild from the target brand’s DNA.

## 30. Transplant test

Ask:

> If the logo, company name, and palette were swapped, could this become an unrelated company?

If yes, strengthen connections to business, brand, product, content, physical world, audience, and interaction.

## 31. Screenshot-deception test

Never approve a page from a 20–30% full-page screenshot alone.

Inspect at 100% desktop, tablet, and mobile.

Check body text, navigation, buttons, inputs, metadata, tables, line length, contrast, icon size, spacing, image quality, density, focus, and overflow.

Beautiful thumbnail ≠ good interface.

## 32. Adversarial critique

Run four critics:

### Client critic
Would this stakeholder actually choose it?

### User critic
Can the intended user understand and use it?

### Brand critic
Could this belong only to this organization?

### Engineering critic
Can it survive implementation and real content?

Each critic identifies 3 strongest decisions, 3 weakest decisions, 1 thing to remove, 1 thing to refine, and 1 risk.

Do not defend the design during critique.

## 33. Quality gates

Before calling work finished, pass:

1. Factual Accuracy
2. Client Desirability
3. Category Fit
4. Brand Specificity
5. Information Architecture
6. Content Quality
7. Composition
8. Typography
9. Imagery
10. Interaction
11. Functional UX
12. Responsive
13. Accessibility
14. Performance
15. Search/Discoverability
16. Implementation
17. AI-Slop
18. Category-Slop
19. Transplant Test
20. 100% Zoom

## 34. Iteration engine

Classify feedback as FACT, CONTENT, BRAND, PREFERENCE, STYLE, COMPOSITION, UX, INTERACTION, RESPONSIVE, ACCESSIBILITY, PERFORMANCE, or IMPLEMENTATION.

Then scope it as MICRO, LOCAL, SECTION, or SYSTEMIC.

Make the smallest intervention capable of solving the issue. Freeze successful sections. Global regeneration only when strategy itself is wrong.

## 35. Redesign mode

When improving an existing design:

1. audit first
2. identify strongest existing decisions
3. freeze what works
4. rank problems by impact
5. fix hierarchy before decoration
6. fix composition before components
7. fix typography before effects
8. fix UX before animation
9. polish only after structure works

Never redesign everything simply because redesign was requested.

## 36. Contest intelligence

Maintain a preference ledger for submitted directions: direction, rating, feedback, survived/declined, client comments, visual characteristics, and content characteristics.

After each signal, update inferred client DNA.

Do not interpret rejection merely as “needs more polish.” Ask whether the visual category, desirability, brand expression, cleverness, convention level, genericness, or trust model was wrong.

**Observed selection > designer theory.**

## 37. Post-decision learning

When a client-selected direction or winner becomes available, run a delta analysis:

- what they chose
- what we built
- where they differ
- what the brief appeared to say
- what their choice reveals
- which rule should change
- which rule should not change

Separate project-specific lessons from generalizable lessons. Do not overfit one result.

## 38. Implementation contract

Before build define framework, CMS, data model, routing, component ownership, design tokens, responsive states, content variability, image pipeline, animation stack, accessibility requirements, analytics, SEO metadata, error states, and loading behavior.

Design must survive real CMS content, long titles, missing images, localization, dynamic data, and editorial updates.

## 40. Pre-build output

Before substantial generation establish:

- source hierarchy
- factual truth
- preference truth
- visual category
- audience
- business goal
- primary conversion
- design thesis
- design calibration
- IA
- content priority
- composition system
- brand device
- type system
- image system
- icon system
- interaction budget
- responsive strategy
- accessibility risks
- performance risks
- search requirements
- anti-DNA
- facts that must not be invented

Then build.

## Final principle

The goal is not “good AI design.”

The goal is work that appears to have been **researched, strategized, art-directed, written, designed, tested, and engineered for this specific organization**.

**QUALITY = TRUTH × PREFERENCE FIT × BRAND SPECIFICITY × COMPOSITION × UX × CRAFT × TECHNICAL CREDIBILITY × IMPLEMENTATION QUALITY**

If any major factor approaches zero, visual polish cannot rescue the result.

**Build less. Justify more. Resolve deeply.**
