# Brief to Build

This example shows how Particular turns project evidence into execution constraints.

## 1. Source hierarchy

```text
1. Final client specification
2. Approved brand guidelines/assets
3. Client-selected visual references
4. Existing website/product
5. Designer references
```

## 2. Factual truth

List locked/verified claims separately from proposed content and placeholders.

## 3. Preference truth

Record what the client chose, rated, rejected, and repeatedly requested. Do not interpret adjectives in isolation when behavioral evidence exists.

## 4. Project DNA

Summarize Brand DNA, Reference DNA, Client DNA, Category DNA, Project DNA, and Anti-DNA.

## 5. Visual category

Name what the client is actually buying, e.g.:

> High-end industrial project company with strong technical proof and direct commercial clarity.

## 6. Calibration

Set evidence-backed values for brand expression, novelty, density, image dominance, CTA prominence, motion, etc.

## 7. Design thesis

> This experience should feel precise, substantial, and confident because buyers need immediate evidence of technical competence. Its dominant behavior comes from real project imagery and brand-derived geometry. It should avoid generic SaaS minimalism and pseudo-engineering UI.

## 8. IA

Map sections to jobs: ORIENT, EXPLAIN, PROVE, COMPARE, NAVIGATE, CONVERT.

## 9. Geometry

Translate direction into concrete grid, spans, image ratios, type measures, alignment datums, and responsive transformations.

## 10. Build contract

Define implementation stack, CMS/data, tokens, image pipeline, interactions, states, accessibility, performance, search metadata, and failure/empty conditions.

## 11. Validation

Run adversarial critics, quality gates, transplant test, AI/category-slop checks, and realistic-size desktop/tablet/mobile inspection.

## 12. Learn

When client selection or usage evidence arrives, update Client DNA and isolate project-specific vs. general lessons.
