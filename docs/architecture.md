# Architecture

Particular is organized as a layered design operating system rather than a single style prompt.

## Layers

1. **Evidence** — facts, references, brand assets, observed preference signals.
2. **Interpretation** — Brand DNA, Reference DNA, Client DNA, Category DNA, Project DNA, Anti-DNA.
3. **Strategy** — visual category, business/user model, design thesis, information architecture, content hierarchy.
4. **Design systems** — composition, typography, imagery, iconography, interaction, responsive behavior.
5. **Build systems** — implementation contract, accessibility, performance, SEO/discoverability, dynamic-content resilience.
6. **Validation** — adversarial critique, quality gates, transplant test, screenshot-deception test.
7. **Learning** — preference ledger and post-decision delta analysis.

## Why layers matter

A visual problem should not be solved at the wrong level. A weak client fit is not fixed by animation. A factual issue is not fixed by stronger typography. A broken hierarchy is not fixed with components.

Always identify the failed layer before changing the design.

## Operating modes

Use focused modules rather than loading every instruction into every task:

- Discover
- DNA
- Concept
- Design
- Build
- Redesign
- Critique
- Polish
- Contest
- Scroll

The canonical rules live in `SKILL.md`; modules are narrow execution views of the same system.
